# CLAUDE.md

**Mapa Vivo — Crônicas dos Imortais**: a browser RPG and world simulation in pt-BR. It is built as a
single self-contained HTML file using vanilla JS, Canvas 2D, a hand-written WebGL2 renderer and
localStorage saves. See README.md for the tech stack, layout and known gaps. Current version: **v8.1** (since 2026-10-27; the
`reference/*_v7.6.html` files stay as the old oracle, and "v7.7" in module/style names marks the visual rework).

**Read [ROADMAP.md](ROADMAP.md) first** (recreated 2026-10-23): the plan to close one playable game cycle (campaign
up to the boss and the chapter end), plus what is left of the tech stack overhaul (Phases 6–7; its history is
`docs/roadmap-historico.md`). Work one step at a time, tick its boxes and update the "Status" line.

Maintainer constraints: no git yet (manual backups). **Browser tests are allowed**: Playwright (headless Chromium) can drive `dist/vtest.html` for tests and screenshots, alongside the Node unit tests (Vitest). The maintainer still plays the build by hand after each step (`docs/smoke-checklist.md`). Prefer Node/TS tooling over Python. Since 2026-10-12 (v7.7) the visuals change on purpose (low poly models from the Tripo `.glb` assets in `arquivos de transferência/`), one short task at a time, each approved by the maintainer from preview images; the rest of the player experience stays as it is. Release = one self-contained HTML file.

The project moved to this machine on 2026-10-12. Earlier work ran on a machine without browser automation, so the history (`docs/roadmap-historico.md`) says "this device" for the old machine and "other device" for where browser tests ran. Claude's notes from that machine are in `_claude/memory/` (see `_claude/README.md`).

The project was first built by an AI in a cloud sandbox (`/home/claude/w`) and exported as a flat
dump. It has been reorganized since: `scripts/legacy/file_map.json` (in the pre-Phase 2 backup zip) maps each old filename to its new path.

## Build model (read this before editing anything)

**Source of truth** = `index.html` + `src/`. Phase 4 (ES modules) is done: all the game's code is in TS modules, and the old concatenated legacy script is gone. Phase 5 (types) is done: domain types, no `@ts-nocheck`, `"strict": true`, interfaces for the state objects, and no `any` placeholder left (the old `Solto` alias is gone; `tipos.test.ts` keeps it out):
- `index.html`: head + body markup. The `<!--@jogo:estilos-->` marker becomes the `<style>` blocks, and `<script type="module" src="/src/main.ts">` loads the game.
- `src/styles/NN_*.css`: style rules, split by section, in `src/manifest.ts` order. `src/styles/icones-pintados.css` becomes `<style id="ico-css">`. Keep that id and one `.ico-<key>{background-image:url(/src/assets/icons/<key>.webp)}` rule per line, because the game parses that block with a regex to fill `ICOS`.
- **`src/main.ts`** (entry) imports the modules (which runs their declarations), then calls the load-time functions in `src/inicio/` in order, then, in the test build only, `instalarGancho()` from `src/dev/gancho.ts`.
- **`src/inicio/base/*.ts`, `src/inicio/modulos/*.ts`:** the code that runs at load (event listeners, `setInterval`s, `try { … localStorage … }` reads, loops that extend data tables, the bootstrap), one `iniciar<Topic>()` per former legacy file (the header names it), called by `main.ts` in the original order. **The order matters**: some loops extend tables that later code reads.
- **ES modules:** ~120 modules by subject: `core/` (config, rng, state, storage, util, main loop), `data/` (all the tunable tables), `hero/`, `map/`, `sim/` (world simulation), `field/` (the expedition/dungeon), `items/`, `econ/`, `forja/`, `runas/`, `survival/`, `creatures/`, `render/` and `render/gl/`, `ui/`, `intro/`, `audio/`, `save/`, `minijogos/`, `expedicao/`. Each module's header says what it holds and where it came from. Every module is typechecked (no `@ts-nocheck`; `tests/unit/tipos.test.ts` keeps it that way) with **`strict` on**: every new parameter needs a type, a table read with a string key needs `Record<string, T>`, and a value that can be `null`/`undefined` must be checked, or asserted with `!` where the code knows it is there (an element of `index.html`, `dungeon.hero` during an expedition). Prefer widening a parameter (`h: Hero | null | undefined`) when the function already handles the missing case. A Phase 3 stage that passes its call on writes `fnBase.apply(this, arguments as Repasse)` and declares `this: unknown`. A value that really takes several shapes gets a union or a structural type (`AlvoHeroi`, `Andante` for whoever walks the map), and the code that knows which one it holds narrows with an `as`; don't reintroduce an `any` placeholder. `npm run tools:sem-nocheck -- --com <option>` shows what `tsc` would report per module with an extra compiler option, without writing anything (`-- <path>` for one module's errors, `-- --tipos` for fields missing from the domain types, `--codigos` by error code). Objects that get fields during play have an `interface Estado<Name>` above them, and tables extended at load are `Record<string, …>`: a field or key a new feature adds must be declared there. The game's own fields on DOM elements (`el._t`, `el._h`…) are declared in `src/dom.d.ts`. **Domain types** (`Hero`, `Item`, `ItemDef`, `InvGrid`, `Monster`, `Animal`, `World`, `Econ`, `Dungeon`, `SaveData`, `GLMesh`, plus helpers like `GradeTela` for an `INV.invGrids` entry…) are in `src/core/tipos.ts` (types only; import them with `import type`); a 4×4 matrix is `Mat4` (`render/gl/geometria.ts`). A field that a new feature adds to one of these objects must be declared there (optional if it appears after load). To change game logic, edit the module (find a name with grep). The shared state (`world`, `camera`, `dungeon`, `econ`, `GL3`, `OPT`) lives in `core/state.ts`, together with the objects that hold what used to be reassigned legacy `let`s under their old names: `TELAS` (canvases, world size, frame loop), `SEL` (selection), `JANELAS` (windows/dialogs), `SOM`, `CACA`, `MEMO`. Also `INV` in `items/inventario.ts` and `MALHA` in `render/gl/geometria.ts`. So it's `INV.invDrag`, `SEL.selectedHero`, `TELAS.canvas`, never a bare `invDrag`. Each of these has an `interface Estado…` (`EstadoTelas`, `EstadoGL3`, `EstadoInv`…) above it: a new field goes there. Fields set at load before any read (canvases, `#viewport`, the WebGL objects made in `glInit`) have their real type and start as `undefined!`/`null!`; fields that can really be empty are `| null`.
- **Imports and state:** a module imports what it uses (relative paths). An imported binding can't be reassigned, so state that changes is a property of an exported object (`INV.invDrag = …`), never a reassigned exported `let`. A missing import is reported by `npm run typecheck` ("Cannot find name"); never silence it with `@ts-nocheck`, or it becomes a global lookup that fails at run time. Don't write code with Bash heredocs (they halve backslashes); Write/Edit are safe.
- Vite bundles it all into one `<script type="module">`, which it places at the end of `<head>` (modules are deferred, so it still runs after the whole document is parsed, before `DOMContentLoaded`). The bundler re-prints the code: comments are stripped (except a `/** … */` doc comment right above a value declaration, which survives: use `//` there for a type-only change), and unused bindings are tree-shaken. `minify` is off and `target` is `esnext`, so the syntax isn't lowered.
- `src/assets/`: `icons/*.webp`, `map/mapa.webp`, `map/mapdata.json` (`MAPDATA`), `art/atlas.webp` (`ATLAS`). Code refers to them as `"/src/assets/…"`, and the build turns each reference into a data URI. `/* @inline-json <path> */ {}` is replaced with that JSON's text in `src/` modules (the plugin's `transform` runs `order: "pre"`, before TypeScript strips comments).
- `src/dev/gancho.ts`: `instalarGancho()` sets `window.__t = {…}`. `main.ts` calls it after all the `iniciar…()` only when `import.meta.env.MODE === "test"`, so the release build drops it (`montagem.test.ts` checks).

The assembly logic (styles, asset/JSON inlining) is `tools/lib/montagem.ts`, used by the Vite plugin `tools/vite-plugin-jogo.ts`. The tests build the real bundle in memory with `tools/lib/construir.ts` (Vite's API, same config, no files written).
`npm run build` → `dist/game.html` (release) + `dist/vtest.html` (test hook). `npm run dev` → dev server with reload.

- **Adding a feature:** put its functions and tables in the module of their subject (or a new `src/<subject>/<topic>.ts`, header `/* ==== v7.7 — … ==== */`), with real imports. Only what must run at load (listeners, timers) goes in a function `iniciar<Topic>()` of a new `src/inicio/modulos/v7.7_<topic>.ts`, imported and called in `src/main.ts` right **before `iniciarQualidadeItens()`** (where the feature modules used to load). Styles: `src/styles/NN_v7.7_<topic>.css`, added to `src/manifest.ts`. To bump the version, change the `<title>` in `index.html` and `MV_VER` in `src/ui/opcoes.ts`.
- `tests/unit/montagem.test.ts` checks that the HTML outside the main script still equals `reference/game_v7.6.html` (only the icon bytes and the script's position may differ). Since Phase 3 the JS differs. `tests/unit/diferencial.test.ts` (runs the same scripted play on the build and on v7.6 in Node and compares the game state step by step) is **retired from the routine since 2026-10-12, by the maintainer's decision: the game no longer needs to match v7.6** (v7.7 changes it on purpose, starting with the heroine model). `npm test`/`verificar` skip it; `npm run test:diferencial` still runs it on demand, but don't keep it green or add to it.

## Code conventions
- All code is in Portuguese (identifiers, comments, UI text). Keep that style. Each module starts with a `/* ==== vX — description ==== */` header listing what it changes.
- Feature modules used to **override earlier functions by wrapping them**
  (`{ const _orig = fnName; fnName = function () { _orig.apply(this, arguments); /* extra */ }; }`). Phase 3 merged
  every chain into one function where it was originally defined, so **don't add wrappers**: edit the function itself. Each
  former layer is a `/* vX — … */` section. A chain that couldn't be inlined became named stages: `fnName` calls
  `fnNameBase`/`fnNameBase2`… (`// etapa de fnName: …`), or a stage with a descriptive name (`hurtMonsterTipos`).
  The tools that did Phases 3 and 4 on the legacy script (`tools:fundir`, `tools:camadas`, `tools:morto`, `tools:folhas`,
  `tools:mover`, `tools:estado`) were deleted with it; they are in the `…backup_pre-init_2026-10-11.zip` backup.
- Tunable constants sit in UPPERCASE tables at the top of modules (`DANO`, `LACO`, `CRAV2`, `CAMPO_VIDA`, `STAT`, …).
- Main global state: `world` (map, heroes, time), `econ` (resources, quiver, mount, flags), `dungeon` (field/expedition mode), `GL3` (WebGL renderer), `camera`, `OPT` (options).
- Icons: `icoTag(key, emojiFallback)` returns painted art if a `.ico-<key>` CSS class exists, otherwise the emoji.
